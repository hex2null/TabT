# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A native macOS terminal emulator written in Rust on top of AppKit, built as a sequence of numbered milestones (step 0 = window, 1 = PTY echo, 2 = dumb rendering, 3 = VT parser). Steps 0–3 are done: it is a working multi-tab terminal with a self-drawn sidebar, groups, themes, fonts, settings, scrollback, and layout persistence. Remaining known gap in the core: the scrollback is not reflowed on resize.

Keep new code comments and UI strings in English (the Rust sources are; the Makefile and `Cargo.toml` still carry some older Chinese comments).

## Commands

Run from the repository root (the workspace root — `Cargo.toml` and `Makefile` live here). The Makefile is the canonical entry point:

- `make test` — `tabt-core` unit tests (`cargo test -p tabt-core`; pure logic, runs on any platform) followed by `tabt-app`'s few (`cargo test -p tabt-app` — the `themes.conf` parser and the `layout.conf` `parse`/`render` round trip, macOS-only because the crate is).
- `make run` — build, bundle into `dist/TabT Dev.app`, codesign, kill any old dev instance, and `open` it. **The GUI must run as a `.app` bundle** — a bare `target/release/tabt` won't get focus or a menu bar (normal macOS behavior for non-bundled processes).
- `make release` — same, but with the shipping identity: `dist/TabT.app`, bundle id `dev.local.tabt`, config in `~/.tabt`. See "Build identities" below.
- `make echo` — the step-1 PTY echo loop (`cargo run --release --bin pty-echo`). **Must be run in a real terminal** (Terminal.app/iTerm); it calls `tcgetattr` on stdin and dies immediately without a tty (e.g. an IDE output panel).
- `make dmg` — build the release app, then `dist/TabT-<version>.dmg` (`bundle/make-dmg.sh`): the app plus an `/Applications` symlink in a compressed read-only image, the usual drag-to-install flow. Uses only system tools, and runs no Finder/AppleScript step: the window's icon size and layout ship as a pre-authored `.DS_Store` (`bundle/dmg-DS_Store`) that is copied into the image, regenerated by hand with `bash bundle/make-dmg-dsstore.sh` when the geometry or the item names change. The default image carries the local dev signature and is refused by Gatekeeper on other Macs; set `SIGN_ID` (Developer ID) and `NOTARY_PROFILE` (a `notarytool store-credentials` profile) to produce a shippable one.
- `make cert` — one-time: create a stable local "TabT Dev" signing identity (`bundle/make-dev-cert.sh`). Without it `make run` falls back to ad-hoc signing, which changes the app's designated requirement on every rebuild, so macOS re-prompts for TCC folder access each time.
- `make bloat` — size audit (`cargo bloat`, needs `cargo install cargo-bloat`); the stripped binary should be ~1 MB.
- Single test: `cargo test -p tabt-core <test_name>` (e.g. `cargo test -p tabt-core print_and_wrap`).

There is no separate lint step (no clippy/fmt target).

The release profile is aggressively size-tuned (`opt-level="z"`, `lto`, `codegen-units=1`, `panic="abort"`, `strip`). `panic="abort"` means a panic anywhere terminates the whole process rather than unwinding — relevant when touching code that parses PTY output or user input.

## Architecture

Two-crate Cargo workspace with a strict dependency direction: `tabt-app` → `tabt-core`, never the reverse.

### `tabt-core` — the VT/ANSI engine

`tabt-core/src/lib.rs`, one file, **deliberately zero-dependency** so it compiles and tests on any platform independent of macOS. Defines `Cell`, `Color`, and `Grid` (fixed-size screen grid in a flat `Vec<Cell>`, indexed `row * cols + col`).

`Grid::feed(&[u8])` is a VT500-style parser state machine (ground / escape / csi / osc, modeled on Paul Williams' diagram) covering SGR pen attributes, cursor movement, erase/insert/delete, scroll regions, save/restore cursor, DEC private modes, IRM, alternate screen, tab stops (a per-column table, edited by HTS/TBC and walked by CHT/CBT), the DEC Special Graphics charset, OSC title and OSC 7 cwd, UTF-8 and wide characters (a wide glyph occupies two cells, the second flagged `WIDE_TRAILER`). Terminal→host replies (DSR/DA) are queued internally and drained by the app layer via `take_replies()`; other state the renderer/input layer reads back through `cwd()`, `cursor_visible()`, `app_cursor_keys()`, `bracketed_paste()`, `mouse_mode()`.

Lines scrolled off the top are pushed into a capped `history` deque. **The renderer must read cells through `view_cell()`, not `cell()`** — `view_cell()` resolves the current scrollback viewport (`view_offset()`, moved by `scroll_view()` / `scroll_to_bottom()`); `cell()` is raw screen access. The alt screen has no scrollback, and lines removed by DL/ED must not enter it. `to_lines()` exports rows as trimmed strings, used by the ~40 unit tests at the bottom of the same file.

### `tabt-app` — the macOS/AppKit layer

Two binaries:

- **`src/main.rs` (bin `tabt`)** — process setup and window/layout construction only. Sets `TERM`/`TERM_PROGRAM` env *before* AppKit starts any thread so forked children inherit a clean env (see the comment there about Apple_Terminal's `~/.zsh_sessions` clash). Builds the container view (sidebar | divider | terminal host | floating toggle), then hands off to `AppController`.
- **`src/bin/pty_echo.rs` (bin `pty-echo`)** — a self-contained PTY loop using **raw `libc`**, no AppKit. It exercises the low-level PTY details (`setsid`, controlling terminal, fd inheritance, raw mode, `SIGWINCH`) that were later lifted into the GUI. Kept permanently as a debugging tool.

**Everything runs on the main thread**, enforced at the type level via `MainThreadMarker`. All custom views are `NSView` subclasses declared with `objc2`'s `declare_class!`.

#### The controller / callback pattern (read `app.rs` first)

`AppController` (`app.rs`) is a plain Rust struct in an `Rc`, created in `main()` and kept alive until `app.run()` returns. It owns every session (each tab = one PTY fd + one `TermView` + a shell pid + a GCD reader token) and handles create/switch/move/close/rename, sidebar layout, theme/font changes, and persistence.

Because ObjC objects can't hold Rust `Rc`s, the sidebar, divider, toggle, menu target, and settings dialog each store a **raw `*const AppController`** and call back through it (plus `extern "C"` trampolines for GCD callbacks). This is sound only because the `Rc` outlives the event loop — preserve that invariant when adding a new view. There is intentionally no reference cycle: the controller owns the views, the views only point back.

#### Data flow

Background **fills** (the terminal's default background, the header/placeholder behind it, the card, the window's own color) go through `view::ns_color_bg`, which carries the opacity setting; everything drawn on top — glyphs, the card hairline, a cell's explicit SGR background — uses `ns_color` and stays opaque, which is what keeps a translucent window readable. `sync_window_chrome` flips `setOpaque:` to agree. Nothing touches `NSWindow::setAlphaValue`, which would fade the text with it.

The cursor blink is a **GCD timer source** owned by `AppController` (`view::attach_timer`), not an `NSTimer`: the controller is a plain Rust struct and cannot be an ObjC target, and making a `TermView` the target instead would have the timer retain a view the controller must be free to drop. One timer for the app, since only the active view is mounted.

PTY master fd → GCD dispatch source (`view.rs`, hand-declared `dispatch_*` externs) → `Grid::feed` → `setNeedsDisplay` → `drawRect:` merges runs of adjacent cells with identical attributes and draws each run once with Core Text (backgrounds/underlines via `NSRectFill`). `keyDown:`/`NSTextInputClient` write back to the fd; `take_replies()` output is written back after each feed; `scrollWheel:` moves the scrollback viewport instead — except on the alternate screen, which has no scrollback: there `Grid::alt_scroll_keys` turns the wheel into cursor-key presses (xterm alternate scroll, DECSET 1007) so the full-screen application scrolls itself. Mouse selection is stored in virtual-buffer rows (`Grid::buf_cell`), not viewport rows, so the highlight stays on its text while the viewport moves. A window/font/sidebar resize recomputes cols/rows from the cell metrics, reflows the grid, and notifies the shell with `TIOCSWINSZ`.

The mouse has **two possible owners**, and every event has to be routed between them (`view.rs`, `mouse_owned_by_app`). An application that asked for tracking (DECSET 1000/1002/1003) gets the event encoded by `Grid::mouse_report_bytes`; otherwise it drives the terminal's own text selection. Three rules are load-bearing and each is easy to get wrong:

- Motion is gated on `mouse_mode() >= MouseMode::Drag`, not on tracking being on at all. Mode 1000 asks for presses and reports no motion, so treating it as a blanket grab would leave a drag doing nothing in either direction.
- Once a press has been taken, the rest of that gesture belongs to the application even if its mode discards the motion — otherwise the drag falls through and extends a selection against an anchor this gesture never set, i.e. from wherever the *previous* selection began. The gesture ends at the button-up, so the release is reported on the strength of the remembered press alone (`mouse_held`): re-testing ownership there would swallow it whenever the user pressed Shift mid-drag, leaving the application with a button it thinks is still down. Buttons chord, so the list holds every held button and each release names its own.
- Holding **Shift** always hands the mouse back to the terminal (the xterm/iTerm2 convention; without it there is no way to select text under tmux or vim), and so does a scrolled-back viewport, whose rows are history the application never drew and whose coordinates would therefore name the wrong line.

Motion reports are deduplicated by cell, since AppKit delivers motion per pixel and the protocol has no sub-cell resolution. Mode 1003's button-less motion is the only reason `TermView` installs an `NSTrackingArea`. Tracking also takes the wheel — an application that asked for the mouse gets button 64/65 reports rather than synthesized cursor keys — but that decision belongs to `scroll_wheel`, not to `alt_scroll_keys`, which knows nothing about tracking: on the alternate screen the Shift escape hatch has nowhere to go but those cursor keys, since there is no scrollback to move. A press taken by the application still clears any leftover selection, which otherwise stays painted over the application's UI and keeps being what ⌘C copies.

`pty.rs` spawns each tab's login shell (`openpty` + `fork` + `setsid` + `TIOCSCTTY` + `execv`), returns a non-blocking master fd, and installs a one-time `SIGCHLD` reaper. Which shell: the Settings → Shell value, else `$SHELL`, else `/bin/zsh`; argv[0] is the basename with a `-` prefix, which is what makes it a login shell. A *configured* shell that isn't executable fails the tab (and raises the caller's alert) rather than falling back silently, because that is a mistake the user can see and fix; an unusable `$SHELL`, which they did not choose here, does fall back. A spawn failure must fail only that tab, never the app. `has_foreground_job()` compares `tcgetpgrp` against the shell pid to warn before closing a tab with a running job. A shell that exits does **not** close its tab: the session is marked ended, `TermView` shows a placeholder, and Enter respawns into the tab's last cwd (`AppController::restart_tab`).

#### Views and state

The sidebar, header, divider, toggle, placeholder and the theme picker are **all self-drawn** (custom `drawRect:`, own hit-testing and drag handling) — the settings dialog (`settings_dialog.rs`) is otherwise the lone user of standard AppKit controls. It holds four panes (Theme / Appearance / Terminal / Shell) in an `NSTabView` set to `NSNoTabsNoBorder` — no tab strip, no box around the content — switched by an `NSSegmentedControl` above it. Rows are placed by `Rows`, a cursor stepping one `ROW_H` at a time, so a new setting is one `rows.next()`; every pane is the same height (`PANE_H`, set by what the theme grid wants) so switching never resizes the window, and every pane's first row starts at the same top edge. The panel deliberately sets **no** appearance of its own: unlike the terminal window, whose chrome is the theme's (`sync_window_chrome`), it is a system panel and follows the system's light/dark setting — the theme is previewed *inside* it, on the Theme pane's cards, not applied to it.

The Theme pane is `theme_grid.rs`: a `ThemeGrid` in an `NSScrollView`, one card per registry entry, each card a **miniature of the app in that theme** — its terminal background, a recessed sidebar in `card_bg` with three row bars, three lines of prompt/listing/cursor in the theme's own palette, then the name and six ANSI chips. It is the picker precisely because a name in a pop-up says nothing about a color scheme. The grid reads `theme::names()`/`by_index` and calls `AppController::set_style`; the dialog only pushes the selection back in (`set_selected`) when it re-seeds. It scrolls because `themes.conf` is user-editable and can hold any number of themes. Like the main window it pins its appearance to `theme::current().is_dark()`, and `sync_window_chrome` re-applies that on every theme change — half the shipped themes are light, and a hard-coded `NSAppearanceNameDarkAqua` (what it used to do) puts dark controls on a light window.

The sidebar is a **floating card**: `card.rs` wraps `SidebarView` in a layer-backed `NSView` inset `CARD_INSET` from the window edges and separated from the terminal by `CARD_GAP`, with the fill, hairline border and corner radius all living on that layer. Three things follow from that and are each easy to break:

- `SidebarView::render` must **not** fill a background, or it covers the card's fill and its rounded corners.
- The terminal and the gutter around the card are the plain theme background; the card is that background stepped one notch deeper (`Theme::card_bg`, a fixed *perceived* luminance step so it lands the same on a near-black theme and a white one), so the panel reads as its own recessed surface and the hairline is left much fainter than the step. A wide, very faint drop shadow then lifts the card off the gutter; keep it near the limit of visibility, because a heavier one tints the CARD_GAP gutter it falls into and that gutter is shared with the terminal, so it becomes a dark seam down the middle of the window. A layer's shadow is drawn outside its bounds, so the card layer must stay **unmasked** — the rounded clip lives on the *content* layer (`card::new`), which has the card's exact frame; putting `masksToBounds` back on the card silently erases the shadow.
- Layer colors are concrete, so `sync_window_chrome` must call `card::apply_theme` on every theme change; unlike the `drawRect:` views the card cannot re-read the theme itself.

The top strip is arranged like the system's sidebar apps: traffic lights at the sidebar's top-left, collapse toggle at its top-right, session title at the terminal's own left edge (`header.rs` spans the host, not the window). All three share `titlebar_center_y()`, and the lights are additionally shifted right by `CARD_INSET` — AppKit positions them against the *window*, so without that they sit hard against the card's rounded corner instead of the standard distance from the edge you actually see. Their baseline x is captured once (`light_x0`) rather than offset in place, because `reposition_traffic_lights` can run when AppKit has not reset the frames and a relative shift would accumulate. **`setTitle:` puts the lights back at AppKit's own coordinates, synchronously**, so `update_title` re-centers them inline right after — deferring that to the next run loop turn (as it once did) lets the window flush in between and the buttons visibly jump on every tab switch. Collapsed, the card is gone, so the toggle joins the lights at the window's top-left and the title's inset grows to clear both.

`CARD_INSET`/`CARD_GAP` also define where the divider sits and how a divider drag maps back to a width — change one and `drag_sidebar_width` has to follow. Collapsing does not hide the card: `relayout` parks it just past the window edge, and `toggle_sidebar` slides it there through `NSAnimationContext` (`set_frame_maybe_animated`). Only the card and the toggle animate — animating the host would reflow the grid and `TIOCSWINSZ` the shell on every frame of the slide.

Two sidebar actions are reachable from the keyboard through the menu and need the row on screen first: ⌃↩ (context menu) and ⌘R (rename in place). Both go through `SidebarView::reveal_active_row`, which expands a collapsed group, scrolls the row into the visible band and **flushes** the redraw — `popUpMenuPositioning…` runs its own modal loop, so a merely invalidated view would still show the pre-scroll rows under the menu. ⌃↩ prefers the row under the pointer; ⌘R deliberately does not, since a rename landing on whatever the mouse rests over would be a nasty surprise.

`menu.rs` sets `MenuTarget` as every submenu's delegate purely to strip the SF Symbols recent macOS attaches to standard menu items; the images are applied at display time, so clearing them at build time does not stick.

`theme.rs` and `settings.rs` hold main-thread-only global state that the drawing code reads on demand, so views don't depend on each other: the current theme in one, and in the other everything the settings dialog can change — font family/size and derived cell metrics, cursor shape/blink (plus the blink *phase*, which the controller's timer flips and typing/output forces back to visible), content padding, background opacity, scrollback depth, the shell and where a new tab starts. Enumerated ones (`CursorShape`, `NewTabDir`) own their persisted `name()`.

`config.rs` persists layout to `~/.tabt/layout.conf` (`~/.tabt-dev` for dev builds, see `branding.rs`) in **hand-written INI** (no serde, to keep the binary small); values are unescaped, so renaming must forbid newlines. The format is `parse`/`render`, with `load`/`save` only `fs` around them — the split is what makes it testable, since `load()` reads a path under `$HOME` and a test written against it would clobber the developer's own config. Everything in `[settings]` travels as one `Settings` struct. Two rules hold for every key: unknown keys and sections are ignored (so a newer version's config stays readable and no migration step is ever needed), and enumerated values are stored **by name**, never by index.

The themes are **data, not source**, and their one home is `bundle/themes.conf` — installed read-only into the app bundle (`Contents/Resources/themes.conf`) and copied verbatim to `~/.tabt/themes.conf` on first run. `theme.rs` compiles in a single theme, `DEFAULT_THEME`, which is *not* the theme the app starts on but the base a parsed `[theme]` inherits each unset field from, plus the one-entry registry left if no file can be read at all; everything else — the settings pop-up, the saved `style` name — goes through the runtime registry (`names()` / `by_index()` / `index_of()`, filled lazily on first use so no ordering against `config::load()` has to be maintained). `ensure_loaded` tries the user copy, then the bundled one, then that base. Four consequences: adding or editing a theme means editing `bundle/themes.conf` (the `shipped_file_parses` test is what guards it — a typo there ships an app with one theme, and the lenient parser will not complain); the user copy is **authoritative** when present, so a shipped theme it omits is gone (its *order* is not the pop-up's — `ensure_loaded` sorts the registry by name, so the file is free to be grouped however reads best), at the price of a theme added by a later version not reaching a copy seeded by an earlier one; the app **only ever reads** it and seeds it only when it is absent (unlike `layout.conf`, which `config::save` rewrites wholesale — hand-written themes there would be dropped by the first save that didn't model them; and a user copy that fails to parse is still the user's, so it is left alone rather than replaced); and parsing must stay lenient, since `panic = "abort"` turns one bad line in a hand-edited file into a dead app. `style` is stored by name, never by index, so adding or reordering themes cannot repoint an existing config. An unbundled `cargo build` binary has no `Contents/Resources` to read, so it comes up on the base theme alone — the GUI is meant to run bundled.

### objc2 version pinning (important)

`objc2 0.5` + `objc2-foundation 0.2` + `objc2-app-kit 0.2` are a **matched set** of APIs (newer major versions exist but are intentionally not used). If a type/method fails to compile, first check whether cargo upgraded a crate out of the set (`cargo tree | grep objc2`) and whether `objc2-app-kit`'s feature list is missing an entry — that crate splits features per Objective-C class, so each `NS*` type used must be enabled as a feature in `tabt-app/Cargo.toml`.

## Bundle

`bundle/Info.plist.in` is the app manifest template (min macOS 12.0, version tracked alongside the crate versions — `make dmg` reads `CFBundleShortVersionString` back out of the built plist for the image name); the Makefile substitutes `__APP_NAME__`/`__BUNDLE_ID__`/`__EXEC__` and writes the result, plus `bundle/AppIcon.icns`, `bundle/themes.conf` (the shipped theme defaults), `bundle/Credits.rtf` (what the standard About panel shows: the blurb and the repository link, as an RTF `HYPERLINK` field) and the binary, into `<app>/Contents/`. Everything that goes into `Contents/` must be copied **before** the `codesign` step — a resource added afterwards invalidates the signature.

### Build identities

The shipped app is **TabT**; `make`/`make run` build a distinct **development** identity so both can be installed and run side by side:

| | `make` / `make run` | `make release` / `make dmg` |
|---|---|---|
| bundle | `dist/TabT Dev.app` | `dist/TabT.app` |
| bundle id | `dev.local.tabt.dev` | `dev.local.tabt` |
| executable (`ps`, `killall`) | `tabt-dev` | `tabt` |
| config dir | `~/.tabt-dev` | `~/.tabt` |

The Makefile passes `TABT_APP_NAME`/`TABT_CONFIG_DIR` to cargo; `tabt-app/src/branding.rs` reads them with `option_env!` (defaulting to the release identity, so a plain `cargo build` still yields the shipping app) and every user-visible name — window title, app menu, quit dialog, empty-pane placeholder — goes through `branding::APP_NAME`. `build.rs` declares `rerun-if-env-changed` for both, so switching identities forces a rebuild of `tabt-app`. `TERM_PROGRAM` is deliberately **not** branded: it stays `TabT` in both, since shell integrations match on it.

`bundle/AppIcon.icns` is generated from `tabt.png` — do not hand-edit it. Use the tracked `app-icon` skill (`.claude/skills/app-icon/`), which documents the non-obvious macOS icon constraints. `.gitignore` deliberately tracks `.claude/skills/` while ignoring the rest of `.claude/`.
