# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A native macOS terminal emulator written in Rust on top of AppKit, built as a sequence of numbered milestones (step 0 = window, 1 = PTY echo, 2 = dumb rendering, 3 = VT parser). Steps 0–3 are done: it is a working multi-tab terminal with a self-drawn sidebar, groups, themes, fonts, settings, scrollback, and layout persistence. The sidebar reports live session state — running/idle/exited, unseen output, a rung bell, the shell's own title. Remaining known gap in the core: the scrollback is not reflowed on resize.

Keep new code comments and UI strings in English (the Rust sources are; the Makefile and `Cargo.toml` still carry some older Chinese comments).

## Commands

Run from the repository root (the workspace root — `Cargo.toml` and `Makefile` live here). The Makefile is the canonical entry point:

- `make test` — `tabt-core` unit tests (`cargo test -p tabt-core`; pure logic, runs on any platform) followed by `tabt-app`'s few (`cargo test -p tabt-app` — the `themes.conf` parser and the `layout.conf` `parse`/`render` round trip, macOS-only because the crate is).
- `make run` — build, bundle into `dist/TabT Dev.app`, codesign, kill any old dev instance, and `open` it. **The GUI must run as a `.app` bundle** — a bare `target/release/tabt` won't get focus or a menu bar (normal macOS behavior for non-bundled processes).
- `make release` — same, but with the shipping identity: `dist/TabT.app`, bundle id `dev.local.tabt`, config in `~/.tabt`. See "Build identities" below.
- `make echo` — the step-1 PTY echo loop (`cargo run --release --bin pty-echo`). **Must be run in a real terminal** (Terminal.app/iTerm); it calls `tcgetattr` on stdin and dies immediately without a tty (e.g. an IDE output panel).
- `make dmg` — build the release app, then `dist/TabT-<version>.dmg` (`bundle/make-dmg.sh`): the app plus an `/Applications` symlink in a compressed read-only image, the usual drag-to-install flow. Uses only system tools, and runs no Finder/AppleScript step: the window's icon size and layout ship as a pre-authored `.DS_Store` (`bundle/dmg-DS_Store`) that is copied into the image, regenerated by hand with `bash bundle/make-dmg-dsstore.sh` when the geometry or the item names change. The default image carries the local dev signature and is refused by Gatekeeper on other Macs; set `SIGN_ID` (Developer ID) and `NOTARY_PROFILE` (a `notarytool store-credentials` profile) to produce a shippable one. `dist/TabT.app` is **deleted** once it is inside the image — the `.dmg` is the deliverable, and a release bundle left in `dist/` is a second launchable copy of the *shipping* identity sitting next to the development one, sharing `~/.tabt` and the `tabt` process name with an installed TabT. Only on success, so a failed image leaves the bundle to inspect; `make release` still leaves it, which is what that target is for.
- `make cert` — one-time: create a stable local "TabT Dev" signing identity (`bundle/make-dev-cert.sh`). Without it `make run` falls back to ad-hoc signing, which changes the app's designated requirement on every rebuild, so macOS re-prompts for TCC folder access each time.
- `make bloat` — size audit (`cargo bloat`, needs `cargo install cargo-bloat`); the stripped binary should be ~1 MB.
- Single test: `cargo test -p tabt-core <test_name>` (e.g. `cargo test -p tabt-core print_and_wrap`).

There is no separate lint step (no clippy/fmt target).

The release profile is aggressively size-tuned (`opt-level="z"`, `lto`, `codegen-units=1`, `panic="abort"`, `strip`). `panic="abort"` means a panic anywhere terminates the whole process rather than unwinding — relevant when touching code that parses PTY output or user input.

## Architecture

Two-crate Cargo workspace with a strict dependency direction: `tabt-app` → `tabt-core`, never the reverse.

### `tabt-core` — the VT/ANSI engine

`tabt-core/src/lib.rs`, one file, **deliberately zero-dependency** so it compiles and tests on any platform independent of macOS. Defines `Cell`, `Color`, and `Grid` (fixed-size screen grid in a flat `Vec<Cell>`, indexed `row * cols + col`).

`Grid::feed(&[u8])` is a VT500-style state machine (ground/escape/csi/osc, per Paul Williams' diagram). Covers: SGR attributes, cursor, erase/insert/delete, scroll regions, save/restore, DEC private modes, IRM, alt screen, tab stops, DEC Special Graphics, OSC title/OSC 7 cwd, UTF-8/wide chars (`WIDE_TRAILER`). Terminal→host replies (DSR/DA) queued and drained via `take_replies()`; other state via `cwd()`, `title()`, `cursor_visible()`, etc. **`take_bell()` consumes** (cleared by seeing). OSC BEL eaten by OSC state, never reaches `execute` (so title-setting doesn't ring bell). **Private CSI prefix** (`?`, `>`, `<`, `=`) routed to `csi_dispatch_private`; only `?h`/`?l` and DECXCPR (`?6n`) act. Final-byte-only dispatch caused vim underline bug (CSI ? 4 m probes modifyOtherKeys, CSI > 4 ; 2 m sets it, both hit `sgr()` as plain SGR 4 with no CSI 24 m to turn off).

Lines scrolled off pushed to capped `history` deque. **Renderer must use `view_cell()` not `cell()`** — `view_cell()` resolves scrollback viewport (`view_offset()`, moved by `scroll_view()`/`scroll_to_bottom()`); `cell()` is raw access. Alt screen has no scrollback; DL/ED lines must not enter it. `to_lines()` exports trimmed rows (for ~40 unit tests); `buf_text()` over whole buffer (history + screen, trailing blanks dropped) = Shell → Export Text.

### `tabt-app` — the macOS/AppKit layer

Two binaries:

- **`src/main.rs` (bin `tabt`)** — process setup and window/layout construction only. Sets `TERM`/`TERM_PROGRAM` env *before* AppKit starts any thread so forked children inherit a clean env (see the comment there about Apple_Terminal's `~/.zsh_sessions` clash). Builds the container view (sidebar | divider | terminal host | floating toggle), then hands off to `AppController`.
- **`src/bin/pty_echo.rs` (bin `pty-echo`)** — a self-contained PTY loop using **raw `libc`**, no AppKit. It exercises the low-level PTY details (`setsid`, controlling terminal, fd inheritance, raw mode, `SIGWINCH`) that were later lifted into the GUI. Kept permanently as a debugging tool.

**Everything runs on the main thread**, enforced at the type level via `MainThreadMarker`. All custom views are `NSView` subclasses declared with `objc2`'s `declare_class!`.

#### The controller / callback pattern (read `app.rs` first)

`AppController` (`app.rs`) is a plain Rust struct in an `Rc`, created in `main()` and kept alive until `app.run()` returns. It owns every session (each tab = one PTY fd + one `TermView` + a shell pid + a GCD reader token) and handles create/switch/move/close/rename, sidebar layout, theme/font changes, and persistence.

Because ObjC objects can't hold Rust `Rc`s, the sidebar, divider, toggle, menu target, and settings dialog each store a **raw `*const AppController`** and call back through it (plus `extern "C"` trampolines for GCD callbacks). This is sound only because the `Rc` outlives the event loop — preserve that invariant when adding a new view. There is intentionally no reference cycle: the controller owns the views, the views only point back.

#### Data flow

**Background fills** (terminal bg, header/placeholder, card, window) via `view::ns_color_bg` (carries opacity); drawn-on-top (glyphs, card line, SGR bg) via `ns_color` (opaque) keeps translucent window readable. `sync_window_chrome` flips `setOpaque:`. Never touch `NSWindow::setAlphaValue` (fades text).

The cursor blink is a **GCD timer source** owned by `AppController` (`view::attach_timer`), not an `NSTimer`: the controller is a plain Rust struct and cannot be an ObjC target, and making a `TermView` the target instead would have the timer retain a view the controller must be free to drop. One timer for the app, since only the active view is mounted.

**Session state** (`Running`/`Idle`/`Dormant`/`Ended`) *sampled* by GCD timer (`sample_states`, `SAMPLE_MS`); can't compute on demand (`Running` needs `tcgetpgrp`). Sidebar redraws on hover/keystroke. Rules:
- Sampler redraws **only on state change** (unconditional refresh = permanent 1 Hz repaint).
- **Separate timer from blink** (blink off by default). Lives with controller; no teardown leaves it firing.
- `end_tab_session`/`restart_tab` set state and refresh immediately (don't wait for sample); must call `refresh_sidebar`/`update_header` explicitly.
- **`Dormant` tab skipped first in loop** (negative `master_fd` read as dead, wrong for unstarted). Without skip, restored tab becomes `Ended` one sample after launch.

**Lazy start:** Restored tabs come back `Dormant` (row, title, cwd, grid; no shell fork). `bootstrap` calls `dormant_tab` then selects one; `select` calls `start_tab_session`. So 20 saved sessions = 1 login shell at launch, not 20. Starting dormant **is** `restart_tab` (never-started and ended differ only in prior shell history; both fork to recorded cwd). `start_tab_session` guards, so `select` calls it on every tab (live tab won't respawn, ended stays for user-triggered Enter). `restart_tab` clears `primed`: sampler skips dormant, so `last_seq` frozen until start; without reset, first sample sees whole rc-file as unseen delta. Dormant holds `master_fd=-1`, `shell_pid=-1`, `reader:None` (same shape as ended). Fork failure puts tab in `Ended`, showing "[Session ended — press Enter to restart]".

Tab label/icon tier from **selection alone**. Unseen output marks row with trailing dot (row brightness = which one you're in, not output). **Activity** mark: background session printed something unseen (counter on `TermView` bumped per read, compared by sampler). Tab counts for nothing until *settled* (seen at prompt with nothing printed whole sample), else restored layout marks every tab on launch (shells' prompts arrive after select resynced only active). **Bell** (`Grid::take_bell`): drained every sample (else latches for next background). Both cleared by selecting tab, which resyncs `last_seq`.

The **session icon** color indicates state and is the row's only mark. Hue carries both user choice and state (green = running, faint = exited, otherwise text tone); a colored running session gets a **green pip badge** on top. Icon colors come from `Theme` via `sidebar::dot_colors`: five from ANSI 16, orange/pink mixed, gray from bright black. Slots are positional per `layout.conf`, which is why variants mix rather than replace. Dormant tabs draw as idle (unstarted sessions shouldn't advertise implementation details). Icon uses SF Symbols 4 (`tab_symbol()` with fallback).

A read that changed the grid's **title or cwd** additionally fires `TermView`'s `meta` callback (the fourth trampoline on `attach`, alongside end/restart/toggle), which is what keeps the sidebar row and the header's meta line current. It compares borrowed `&str`s against the last values reported, so a read that moved neither — nearly all of them — allocates nothing.

PTY fd → GCD dispatch source (`view.rs`, hand `dispatch_*` externs) → `Grid::feed` → `setNeedsDisplay` → `drawRect:`. Render merges adjacent cells, draws runs with Core Text (bg/underline via `NSRectFill`). `keyDown:`/`NSTextInputClient` write fd; `take_replies()` after each feed. `scrollWheel:` moves scrollback viewport, except alt screen: `Grid::alt_scroll_keys` turns wheel into cursor keys (xterm DECSET 1007). Mouse selection in virtual-buffer rows (`Grid::buf_cell`), not viewport, so highlight stays on text. Resize recomputes cols/rows, reflows grid, `TIOCSWINSZ` shell.

Mouse has **two owners** (`view.rs`, `mouse_owned_by_app`): app if tracking (DECSET 1000/1002/1003), else terminal selection. Three rules:
- Motion gated on `mouse_mode() >= Drag`, not just tracking on. Mode 1000 (presses only) would leave drag doing nothing.
- Once press taken, gesture belongs to app even if mode discards motion; release reported via remembered press (`mouse_held`). Buttons chord; list holds all held, each release names its own.
- **Shift** returns mouse to terminal (xterm/iTerm2 convention; needed for text under tmux/vim). Scrolled-back viewport also returns (rows are history app never drew).

Motion deduplicated by cell (AppKit gives per-pixel). Mode 1003 (button-less motion) only reason for `NSTrackingArea`. Tracking takes wheel (buttons 64/65) vs cursor keys. App press clears stale selection (otherwise stays on UI, is what ⌘C copies).

`pty.rs` spawns login shell (`openpty`+`fork`+`setsid`+`TIOCSCTTY`+`execv`), returns non-blocking fd, installs `SIGCHLD` reaper. Shell: Settings → Shell value, else `$SHELL`, else `/bin/zsh`; argv[0] = `-basename` (login shell). Configured shell not executable = fail tab (user can fix); unusable `$SHELL` = fall back. `has_foreground_job()` via `tcgetpgrp`. Exited shell marks tab `Ended`, shows placeholder; Enter respawns via `AppController::restart_tab`. `restart_tab` only safe for shell-less sessions (ended or dormant); toolbar Restart first SIGHUP live session, then respawn. **Critical:** `TermView::restart` must run before `attach_reader` (reader builds dispatch source on view's fd, not handed fd; without swap, still `-1` from `end_session`, source never fires).

#### Views and state

**Self-drawn views:** sidebar, header, divider, toggle, placeholder, theme picker (custom `drawRect:`, hit-testing, drag). **Settings dialog** (`settings_dialog.rs`) only uses standard AppKit controls: five panes (Theme/Appearance/Toolbar/Terminal/Shell) in `NSTabView` (no tabs, no border), switched by `NSSegmentedControl`. Rows placed by `Rows` cursor (`rows.next()`). Numeric settings (font size, padding) are continuous sliders, rounded/applied on whole-point change only (avoid per-pixel reflow/TIOCSWINSZ). All panes same height (`PANE_H`), panel width = Toolbar pane (1:1 title bar), switch never resizes. Esc via hidden `NSButton` with key equivalent (responder method doesn't reach plain window with focused text field). Panel sets **no appearance** (system light/dark; theme previewed inside, not applied).

**Theme pane** (`theme_grid.rs`): `ThemeGrid` in `NSScrollView`, one card per registry entry. Each card = miniature app (terminal bg, recessed sidebar, prompt/listing/cursor lines, name, ANSI chips). Picker because name alone says nothing. Reads `theme::names()`/`by_index`, calls `set_style()`. Scrolls (user themes unlimited). Pins appearance to `theme::current().is_dark()`.

Sidebar is a **floating card** (`card.rs`): layer-backed `NSView` inset `CARD_INSET` from edges, gap `CARD_GAP` from terminal. Corners concentric with window: radius = `WINDOW_RADIUS − CARD_INSET` (~26pt measured), curve continuous not circular (`setCornerCurve:`). Three critical details:
- `SidebarView::render` must not fill background (covers card's fill/corners).
- Card depth = theme background stepped one notch (fixed luminance step, `Theme::card_bg`). Faint drop shadow lifts card; heavier shadow tints shared gutter. Layer must stay **unmasked** (rounded clip on content layer only); `masksToBounds` erases shadow.
- Layer colors concrete; `sync_window_chrome` calls `card::apply_theme` on theme change.

The top strip is arranged like the system's sidebar apps: traffic lights at the sidebar's top-left, its search and collapse buttons at the far end of that same strip (`toggle.rs`, one `StripButton` class in two roles), session title at the terminal's own left edge (`header.rs` spans the host, not the window). The band is a real **`NSToolbar`** (`toolbar.rs`) over a transparent, full-size title bar: the toolbar owns the row, so `titlebar_center_y()` follows *it* (`band_h() / 2`, the band read back off `contentLayoutRect` rather than assumed — with a toolbar attached that height is the system's, and `HEADER_H` is only the fallback), and everything else is placed onto that line. `header.rs` is what paints the band in the theme's background and draws the title on it; the toolbar contributes only the button.

The sidebar's top level is **one ordered list** (`Model::items`, `Vec<Node>` of `Tab`/`Group`), merged so groups can sit between sessions. Groups are named by ordinal (`Press::Group(gi)`), kept in `[group]` sections; nothing outside `Model` knows about item positions. Drag drops name the item they land *before*, not an index, since the dragged item's removal renumbers the list. `Model::place_tab` resolves after detaching; `Model::reorder_group` before removing.

Dropping shows: **insertion line** between rows, or — over a collapsed group — **container highlight** (since collapsed groups have no drawn gap). The line is indented for into-group drops; `GROUP_EDGE_BAND` at a group's top means "above this group, at the top level". Collapsed groups with no sessions have no drop target between them.

**Search box** only draws while it has keyboard or is animating; ⌘F opens/closes (when empty), or leaves it open if it has a query (text is the user's work). Losing keyboard doesn't close it; only Esc, ⌘F on empty, or the magnifier do. This splits "search is on" (`searching`) from "keyboard focus" (`has_keyboard`). Sidebar collapse keeps the box but returns keyboard. Animation is `SEARCH_ANIM` (GCD timer); the box clips to reveal height, opening like a drawer. Focus ring is stroked inside to avoid clip edges.

**Settings → Toolbar** customizer (`toolbar_editor.rs`) draws buttons being chosen (not checkboxes). One editable row per group (AI, Common), buttons at window size: theme bg, icon at `ICON_PT` tone, 44pt item box, capsule. Metrics measured from `NSToolbarItemViewer` frames. Row clips overflow with ellipsis (real toolbar has whole window). **Button's group is fixed** (`Entry::group`); AI row = launchers only, drag cannot cross. Palette split same way, each half labeled. `rows()` reads divider position to resolve odd configs (e.g., `claude` after divider goes to AI row). No draggable Space: break between capsules is row break.

Two keys control toolbar state: `toolbar_hidden` (visibility, stored as *hidden* set so new buttons appear), `toolbar_order` (arrangement). New buttons not mentioned in order are appended per `CUSTOMIZABLE`, except `Entry::default_on` ones (AI launchers, interrupt, restart, fonts) start in palette. `SPACE_KEY` is the divider in stored order — keys before are AI row, after are Common. Old configs with no divider remap by button's own row. Drag commits on mouse-up via `Toolbar::rebuild`; a press that doesn't move does nothing.

Toolbar defaults: `claude`, `codex` (shell resolves name), clear line, clear, screenshot, Export Text, Reveal in Finder. Palette: Home, copy, paste, and AI launchers (`gemini`, `aider`, `cursor-agent`). **Clear** sends `⌃L` to PTY (shell repaints); **Interrupt** sends `⌃C` (tty turns it into SIGINT for foreground process). `copy:`/`paste:` are targetless (belong to focused `TermView`); others target `MenuTarget` for validation. Sidebar/font buttons don't need an active session; others do.

Icon **tone/size = theme, not system**: symbol image baked with hierarchical color (`ICON_DIM` from foreground, `ICON_PT` point size), since AppKit tints template in control color and sizes toolbar larger than strip buttons (side-by-side shows difference). Baked color concrete; `sync_window_chrome` re-applies on theme change (`Toolbar::apply_theme`).

**Search/collapse exist twice:** Expanded = card's own (`toggle.rs`, `StripButton` in two roles), self-drawn top-right (ride card, `relayout` parks off edge). Collapsed = toolbar pair (between lights and title). Swap via `Toolbar::set_shown` (removes/re-inserts items; `NSToolbarItem` no `isVisible` setter), once per collapse. Both send same selectors as View menu (`toggleSidebar:`/`findSession:`).

Three further things about that toolbar are the result of measurement, not documentation, and each cost a rewrite:

- The button is **not** `NSToolbarToggleSidebarItemIdentifier`. That reserved item wants a window whose content view controller is an `NSSplitViewController`; with a floating card AppKit resolves no target for it and ships it permanently disabled, without ever calling `validateToolbarItem:`. What is there instead is a plain bordered image item carrying the system's own `sidebar.left` symbol — the same button to look at and to click — pointed at `MenuTarget`'s `toggleSidebar:`, the selector the View menu already used. The target is set **explicitly** (`AppController::set_toolbar_target`, from `main` once that object exists): `MenuTarget` is only the window's *delegate*, and an item whose target the responder chain cannot resolve is drawn disabled.
- **The session title is not a toolbar item.** It has to start at the terminal's left edge, which moves with the sidebar, and AppKit measures a custom item view exactly once — when the item is inserted. `minSize`/`maxSize`, `invalidateIntrinsicContentSize` and `setNeedsLayout` up the chain all leave it where it was first placed, so a title item could be positioned but never re-positioned. `HeaderView` spans exactly the terminal pane, so it gets that alignment for nothing.
- Sizing a custom item view at all is `setMinSize`/`setMaxSize` **or nothing**: with constraints or an `intrinsicContentSize` alone the item reports itself visible, its frame reads correctly, and `drawRect:` is simply never called.

Traffic lights shift right by `CARD_INSET` (AppKit positions vs window, not card edge). Baseline x is captured once in `light_x0`; `setTitle:` syncs them after repositioning. `update_title` skips if string unchanged; `update_header` (directory/shell) updates separately on every `cd` to avoid relayouting title bar per keystroke. Collapsed, title inset grows past `TOGGLE_RIGHT_X` (toolbar button position); expanded, plain `TITLE_INSET` from terminal edge (or clears lights if sidebar docked right).

`CARD_INSET`/`CARD_GAP` define divider sit, drag mapping, and **min width** (sidebar footprint + `MIN_TERM_W`). Recomputed in `relayout` (sidebar width moves on drag/collapse). Limit enforced both sides: `set_sidebar_width` bounds by available space, guards `clamp`. Window narrower than limit gets **widened** (old `layout.conf`, expanded sidebar after collapse). Only width bounded; `0` height uses AppKit default. Collapse parks card past window edge via `toggle_sidebar` + `NSAnimationContext` (`set_frame_maybe_animated`). Only card animates (animating host reflowed grid, `TIOCSWINSZ` per frame).

⌘` (unshifted, "Last Session") toggles to previously active session via `select`'s recording (silent if nothing to return to or tab closed).

Two sidebar actions need row on-screen first: ⌃↩ (context menu) and ⌘R (rename). Both via `SidebarView::reveal_active_row`: expands collapsed group, scrolls into view, **flushes** redraw (menu's modal loop else sees pre-scroll rows). ⌃↩ uses pointer row; ⌘R deliberately doesn't (avoid surprise rename on mouse position).

`menu.rs` sets `MenuTarget` as every submenu's delegate purely to strip the SF Symbols recent macOS attaches to standard menu items; the images are applied at display time, so clearing them at build time does not stick.

`theme.rs` and `settings.rs` hold main-thread-only global state that the drawing code reads on demand, so views don't depend on each other: the current theme in one, and in the other everything the settings dialog can change — font family/size and derived cell metrics, cursor shape/blink (plus the blink *phase*, which the controller's timer flips and typing/output forces back to visible), content padding, background opacity, scrollback depth, the shell and where a new tab starts. Enumerated ones (`CursorShape`, `NewTabDir`) own their persisted `name()`.

`config.rs` persists layout to `~/.tabt/layout.conf` in **hand-written INI** (no serde). Sidebar order stored as repeating `[tabs]` and `[group]` sections in draw order; old configs' single `[tabs]` first matches restored order (no migration). No newlines in values; labels sanitized via `config::sanitize_label` (rename box, OSC 0/1/2 title), paths via `config::sanitize_path` (OSC 7). Both truncate by **characters** (byte-slice mid-char panics under `panic="abort"`). Format splits `parse`/`render` from `load`/`save` for testability. Window **position** persisted separately: size uses `0` (invalid width); `window_x`/`window_y` are `Option`s, absent means "center". Origin read at save time, not tracked. `[settings]` travels as one `Settings` struct. Enumerated values stored **by name**, not index; unknown keys/sections ignored for forward compat.

Tab name priority: ⌘R rename > OSC 0/1/2 title > directory. OSC titles (from ssh/tmux/vim) are rare since stock zsh doesn't set one (no `Apple_Terminal` hook, `TERM_PROGRAM=TabT`). **`auto = true`** marks derived names only; absent key means pinned. This keeps configs from silently discarding renames. `tab =` always written so restored sessions read correctly before shell reports title.

Themes are **data** (not source), home: `bundle/themes.conf` (bundled, copied to `~/.tabt/themes.conf` on first run). `DEFAULT_THEME` is fallback/base, not startup theme. Runtime registry filled lazily (`names()` / `by_index()`); `ensure_loaded` tries user copy, bundled, then base. **User copy is authoritative** if present (shipped theme omitted = gone; later version's new theme won't reach old copy). App only reads, never rewrites (unlike `layout.conf`). Bad parse is left alone (parse failure under `panic="abort"` = crash). `style` stored by name, never index. Unbundled `cargo build` has no resources, uses base theme only; GUI meant to run bundled.

### objc2 version pinning (important)

`objc2 0.5` + `objc2-foundation 0.2` + `objc2-app-kit 0.2` are a **matched set** of APIs (newer major versions exist but are intentionally not used). If a type/method fails to compile, first check whether cargo upgraded a crate out of the set (`cargo tree | grep objc2`) and whether `objc2-app-kit`'s feature list is missing an entry — that crate splits features per Objective-C class, so each `NS*` type used must be enabled as a feature in `tabt-app/Cargo.toml`.

## Bundle

`bundle/Info.plist.in` is the app manifest template (min macOS 12.0, version tracked alongside the crate versions — `make dmg` reads `CFBundleShortVersionString` back out of the built plist for the image name); the Makefile substitutes `__APP_NAME__`/`__BUNDLE_ID__`/`__EXEC__` and writes the result, plus `bundle/AppIcon.icns`, `bundle/themes.conf` (the shipped theme defaults), `bundle/Credits.rtf` (what the standard About panel shows: the blurb and the repository link, as an RTF `HYPERLINK` field) and the binary, into `<app>/Contents/`. Everything that goes into `Contents/` must be copied **before** the `codesign` step — a resource added afterwards invalidates the signature.

### Build identities

The shipped app is **TabT**; `make`/`make run` build a distinct **development** identity so both can be installed and run side by side:

| | `make` / `make run` | `make release` / `make dmg` |
|---|---|---|
| bundle | `dist/TabT Dev.app` | `dist/TabT.app` |
| bundle id | `dev.local.tabt.dev` | `dev.local.tabt` |
| executable (`ps`, `killall`) | `tabt-dev` | `tabt` |
| config dir | `~/.tabt-dev` | `~/.tabt` |

The Makefile passes `TABT_APP_NAME`/`TABT_CONFIG_DIR` to cargo; `tabt-app/src/branding.rs` reads them with `option_env!` (defaulting to the release identity, so a plain `cargo build` still yields the shipping app) and every user-visible name — window title, app menu, quit dialog, empty-pane placeholder — goes through `branding::APP_NAME`. `build.rs` declares `rerun-if-env-changed` for both, so switching identities forces a rebuild of `tabt-app`. `TERM_PROGRAM` is deliberately **not** branded: it stays `TabT` in both, since shell integrations match on it.

`bundle/AppIcon.icns` is generated from `tabt.png` — do not hand-edit it. Use the tracked `app-icon` skill (`.claude/skills/app-icon/`), which documents the non-obvious macOS icon constraints. `.gitignore` deliberately tracks `.claude/skills/` while ignoring the rest of `.claude/`.
